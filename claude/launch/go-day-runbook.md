# GO-DAY RUNBOOK — launch as a checklist, not an improvisation
**2026-09-10. Two distinct days: SUBMISSION DAY (her GO fires it) and
LISTING-LIVE DAY (the review queue decides it; we execute the cascade).
Every asset referenced exists and is indexed in claude/launch/README.md.**

Ordered; J = her taps, C = mine. Total her-time ≈ 30 min.
1. C: final claims re-verify — search the Claude directory for podcast/
   analytics connectors; screenshot; lock which scoped claims are true.
2. C: freshness pass — demo account tools return real data (B4 check);
   rate limits answering; setup page + /claude + privacy resolve.
3. J: open claude.ai admin settings → directory → submissions (Team org).
4. J pastes / C relays: the §1 metadata pack from listings-and-rehearsal.md
   field-by-field (name, slug podlink, tagline, description, categories,
   icon, docs URL with utm, privacy URL, support@, use-case + data-handling
   answers, 7 compliance acks).
5. J: test-account credentials into the form (B4 password — hers).
6. J: SUBMIT. C: log submission date/time in SESSION_LOG; calendar note
   "escalate via mcp-review@ after ~3 weeks of silence"; weekly dashboard
   check joins the Monday GSC pull.
7. C (same sitting, if account access permits) / J (if accounts needed):
   PulseMCP + Glama + Smithery submissions from the same pack. Skip any
   that demands an open-source repo — no loss.
8. NOTHING POSTS TODAY. Submission is silent by design; the drip calendar
   continues unaffected.
(ChatGPT directory = its own later Day 0 after the Claude listing lives:
needs OpenAI org, domain verification TXT, terms page, test-case matrix —

## DAY L — LISTING-LIVE DAY (trigger: the listing appears; not ours to pick)
Morning-of discovery is fine; if it lands on a weekend, execute Monday.
1. C: verify by browsing the directory; screenshot the listing + the
   category state. Scoped claims unlock ONLY per what's on screen.
2. C: /features/mcp index flip (its checklist completes at listing-live) +
   sitemap add + present-tense copy pass + /claude gains the "find us in
   the Claude directory" line + GA4 annotation for the date.
3. C: changelog tentpole entry (drip calendar: tentpole interrupts drip).
4. C: voice-guide onlyness rows flip per the screenshot evidence.
5. J: LinkedIn launch post — sample D + the listing line, comment gate
   "comment PODLINK". Post early weekday, never Sunday. THE 2-HOUR WINDOW:
   she replies to every comment from her phone; the 10 objection answers
   (linkedin-one-pager.md) are her paste-speed crib sheet. If the 2 hours
   can't be blocked, move the post day — never post into silence.
6. J: X post — sample B (the measurement one-liner) + link. Video goes
   native on both IF recorded by then; otherwise it joins the numbers post.
7. J→C: allies — B-group reminded morning-of; C-group clients asked for
   one real-proof comment each; D-group commenters DM'd within 48h (her
   sends, C drafts + tracks).
8. C: harvest — comments → objection inventory + next drip's content;
   activation metric = connected-accounts count (server-side), checked
   daily for the first week.

## DAY L+2..7 — THE NUMBERS POST
Rondot format, REAL numbers only (GA4 export + connected-accounts count;
universe stated; no rounding up). If the numbers are small, the honesty
register IS the post. C drafts from live data; J edits and sends.

## Standing rules that bind all of it
External comms fire only inside this runbook after GO · claims survive
screenshots · no public dates for unshipped work · drips continue on
cadence around the tentpole · every DM and post is sent by HER.
