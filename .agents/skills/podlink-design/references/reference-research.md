# Reference research workflow

Use before major marketing/feature redesigns.

## Goal

References should expand design judgment without turning Podlink into a collage of other products.

Collect 3–5 high-quality references that solve a related problem.

Useful sources include:

- Refero,
- Landdding,
- Godly,
- Awwwards,
- direct product sites,
- real creator/analytics products,
- design-system/component docs when evaluating a primitive.

## Record each reference

Use this format:

| Reference | Problem solved | Borrow | Do not borrow |
|---|---|---|---|
| Product/site + URL | What makes it relevant | Specific hierarchy/IA/interaction/type/visualization/responsive behavior | Palette, layout clone, brand-specific motif, irrelevant complexity |

## What to look for

### Marketing

- how quickly the product appears,
- hero hierarchy,
- screenshot crop/scale,
- section composition variety,
- proof placement,
- CTA hierarchy,
- narrative pacing,
- mobile treatment.

### Product UI

- navigation,
- density,
- status patterns,
- toolbars/filters,
- object identity,
- empty/setup states,
- responsive adaptation.

### Analytics

- metric hierarchy,
- comparison context,
- chart selection,
- filtering,
- source/provenance,
- sharing/public report behavior,
- mobile data treatment.

## Strong reference types for Podlink

### Dub

Useful for compact analytics hierarchy, link/report sharing and stakeholder-friendly public analytics patterns.

Borrow patterns, not brand styling.

### OpenPanel

Useful for metrics-first analytics and matching visualizations to analytical questions.

### Refero

Useful for real product screenshot presentation and workflow-level references.

### ScrollCraft

Useful for acquisition-page process: grammar, visual peak, signature move, separate mobile composition and visual verification.

Not a default product UI system.

## Rules

- Never copy a whole page.
- Never inherit a reference's palette because it looks premium.
- Never import a component library merely because a reference uses it.
- Prefer references that demonstrate the same user decision, not merely the same industry.
- Product truth outranks reference aesthetics.

## Output

The reference table belongs in the design brief, PR description or linked design note for major work.
