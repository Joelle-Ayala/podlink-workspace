# Product UI

Use for dashboard/workspace/settings/episode surfaces.

## Product UI is not marketing UI

The app is a working environment. Optimize for comprehension, task completion and trust before drama.

## Default hierarchy

1. Context: what show/episode/object am I looking at?
2. Primary state/data: what matters now?
3. Primary action: what can/should I do?
4. Exceptions/setup: what is blocking value?
5. Secondary data/details.

## Regions, not card piles

Use a card when the content behaves like an independent object/module.

Do not card-wrap information merely because it exists.

Prefer:

- open layout regions,
- dividers,
- alignment,
- grouped tables/lists,
- section headings,
- contextual toolbars.

Avoid card-inside-card and rows of equal-weight KPI tiles when one metric is clearly more important.

## Episode as a core object

Episode UI should progressively unify:

- title/date/artwork,
- download/video performance,
- transcript state,
- transcript/source content,
- derived content/assets,
- channel/distribution state,
- share/report state.

Do not make each capability feel like a separate app.

## Setup states

Setup guidance should be contextual and disappear as steps are completed.

Good:

- Connect YouTube — see video performance next to audio.
- Add OP3 prefix — begin independent download measurement.

Bad:

- permanent onboarding checklist competing with live product content.

## Controls

- Keep destructive/high-impact actions explicit.
- Avoid icons without text when meaning is not standard.
- Use labels that describe outcomes.
- Keep filters close to the data they alter.
- Do not expose vendor terminology when a user-language label exists.

## Status

Status should combine shape/text/icon where useful; never color alone.

Examples:

- Measuring downloads
- Waiting for data
- Transcribed
- YouTube connected
- Report live

## Empty states

Empty states should explain the next useful action and why it matters.

Do not fill empty product areas with fake sample data unless clearly labeled as a demo/example mode.

## Density

Marketing: spacious.
Product: purposeful density.

Avoid oversized marketing typography in operational screens. Preserve scanability.

## Cross-system coherence

MagicAI, Analytics and BioLink surfaces should progressively converge on:

- semantic colors,
- typography,
- action hierarchy,
- status language,
- navigation behavior,
- spacing,
- episode/show identity patterns.

Do not require a full rewrite before improving the highest-value surfaces.
