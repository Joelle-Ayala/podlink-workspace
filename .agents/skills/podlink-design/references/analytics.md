# Analytics

Use for Podcast Analytics, Show Report, True Audience, Media Kit and future social/channel reporting.

## Start with the question

A chart or metric only belongs if it helps answer a real question.

Examples:

- How is the show doing?
- Which episode is outperforming?
- Where is the audience consuming it?
- What changed?
- What should I show a sponsor?

Do not begin with “what chart can we add?”

## Visual hierarchy

A useful analytics surface normally has:

1. one primary metric/question,
2. context/comparison,
3. trend,
4. supporting breakdowns,
5. source/provenance.

Do not give every number identical visual weight.

## Comparison

A naked number is weaker than a number with context.

When the data permits, compare against:

- previous episode,
- prior period,
- rolling show baseline,
- historical range,
- channel mix.

Never fabricate a comparison if the snapshot/history does not exist.

## Visualization selection

- time/change → line or area,
- ranked categories/share → horizontal bars or ranked list,
- conversion stages → funnel,
- movement/flow → flow/Sankey only when it materially clarifies movement,
- single KPI → number + comparison/source, no chart required.

Pie/donut charts are not default share charts. Use only when part-to-whole is the actual question and categories are few.

## Color

Orange is the focal signal, not every series.

Use neutrals for supporting series. Add additional colors only when semantic distinction is necessary and accessible.

Avoid rainbow dashboards.

## Provenance is product value

Where relevant, visibly label sources:

- OP3
- YouTube
- Podlink page
- Instagram / future connected source

The “where did this number come from?” answer should be easy to find.

For sponsor-facing views, provenance may be part of the value proposition.

## Episode relationship

Where possible, analytics should remain attached to the episode object rather than split into disconnected channel dashboards.

The long-term visual model is:

Episode → audio → video → derivative assets → distribution → performance.

## Show Report

A public report should prioritize clarity over dashboard power.

It should be:

- understandable without training,
- safe to share,
- current,
- visually credible,
- explicit about source where trust matters,
- printable/screenshot-friendly even though the product is a live link.

Do not expose internal controls or admin complexity.

## True Audience

When audio + video are combined, do not imply the metrics are identical concepts.

Make the composition show connected sources clearly. Use totals only when the product definition supports the claim; retain source breakdowns.

## Small/new shows

Do not punish a small show with an empty “enterprise analytics” experience.

Useful alternatives:

- setup progress,
- source health,
- recent episode list,
- available platform data,
- explanation of when trends will become meaningful.

## Mobile

Prioritize:

- primary number,
- trend,
- source,
- most useful breakdown.

Wide tables should become ranked lists, scroll regions or purpose-built mobile summaries rather than microscopic tables.
