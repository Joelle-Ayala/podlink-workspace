# BioLink / Presence

Use for `podlink.fm`, public creator/show pages and the editor that powers them.

## Positioning

Presence is a Podlink product family, not a separate BioLink product.

The creator/show owns the page visually; Podlink supplies the system.

## Public page priorities

1. creator/show identity,
2. current/featured content,
3. listening/watch destinations,
4. relevant links/offers,
5. Podlink attribution/chrome last.

## Media-first

Use real:

- show art,
- episode art,
- creator imagery,
- videos,
- clips.

Do not substitute generic icon cards for content that has real media.

## Link treatment

Not every link needs a large rounded card.

Choose weight by importance:

- featured episode/video can be rich media,
- primary destinations can be stronger actions,
- secondary links can be simpler rows/text links.

Avoid “stack of 14 identical buttons.”

## Editor coherence

The editor should use the same Podlink action hierarchy/status/typography as Analytics even if the underlying BioLink implementation remains separate.

Preview should feel like the public page being edited, not a different design language embedded inside Podlink.

## Analytics connection

Where page views/link clicks appear in Podlink analytics, naming and source language should connect them clearly to the Presence module.

## Customization

Creator customization should produce authored identity without allowing the system to become visually broken.

Prefer controlled choices:

- surface/theme,
- typography presets if supported,
- image/media choices,
- section ordering,
- emphasis.

Do not expose hundreds of tiny styling controls merely because BioLink can.

## Mobile

The public page is mobile-first by usage. Test 390px and 360px before desktop polish is considered complete.
